# Exploratory cumulative resource-patch evolution

Prospective registration: inputs and source are reviewed before any build or scientific life. This is a bounded
test of cumulative evolutionary accessibility under the explicit plan revision committed in `52e390a`.
It does not claim formal section 0.4 admission or a demonstrated memory mechanism.

The unchanged AO genome already collects replenished food, and the preceding stock-modulation intervention
finds a useful sensory contribution. The next question is whether ordinary evolution can improve resource
acquisition while retaining earlier abilities, using the same evolved genome across environments.

Eight generations import every ordered survivor of AO balanced24, with fresh native seed 53234. Ordinary
32+224 search and physical prices remain unchanged. Four patch, two POOL and two persistent pursuit lives
make up each eight-life selection draw; eight recheck lives repeat that allocation. No named behavior receives
a bonus, and physical rules stay fixed throughout the search.

Generation 8 rank 0 is the primary endpoint. Generation 4 rank 0 is a passive, predetermined observation.
Neither can be replaced based on confirmation results. AO start and both endpoints each receive 512 fresh
shared lives in five environments: trained patches, POOL, persistent pursuit, earlier longer cue gaps, and a
reserved four-patch/radius 3–5/refill 100–200 combination. The latter changes only those patch-count, radius and
refill-period fields.
Confirmation seeds are 52,490,000–52,490,511; native and confirmation namespaces are independently audited.

Lead with replenished and total food, alongside production F, empty clicks and every physical cost. Measure
older capture retention directly, using the existing 90% diagnostic margin. This permits some loss and does
not guarantee cumulative retention. Compare one unchanged genome across environments without further
adaptation. Fresh life seeds and one reserved parameter combination do not establish broad generality or
replication across independent evolutionary searches.

The maximum is **28,222 calls**: 20,534 search research, 7,680 confirmation and eight startup engineering
lives. Package caps are **5,400 CPU /3,600 wall seconds**, including 120 CPU /120 wall reserved for preparation
and terminal work. Search receives at most 4,080 CPU seconds, with 1,200 reserved for confirmation and cleanup.
One worker uses two kernel threads, a 4 GiB owned-RSS stop, 8 GiB address-space cap and 4 GiB host-memory
reserve. There is no automatic retry, cap extension or favorable-midpoint substitution.

`PROTOCOL.md` describes the design; `protocol.json` binds every source and input byte. `reviews/` contains
authorship, source checks and independent source/input reviews. `namespace/` and `namespace_references.json`
retain seed evidence. Runtime release is a separate root-owned action after prospective publication.
