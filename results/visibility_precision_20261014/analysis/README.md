# Independent AB reader

The reader is bound to protocol `1d53d07a7aa682f81f04d641c655a6018da0f278f74cfefdd4bcbcc6ab5a7ad7`.
Preparation contains two fixed Z founders, one recorded initialization per background, and four configs.
Independent input review verified all 38 local and 35 production pins, all 64 initialized rows by replaying
recorded mutations, and both config pairs. It made no random draws, compiled no kernel and ran no lives.
Readiness and a complete first monitored attempt remain necessary before any outcomes can be emitted.

This narrowly adapts Z's native reader and preserves the exact whole-life Y/Z58-column accountant. The two
policies use 4 generations at 3+4 lives and 1 generation at 12+16, with4,096 selection calls per founder/arm.
The retained selection helper differs only in the initial/recheck seed ranges and pooled-score weights;
its original bytes and both helper source hashes are retained. The original ordinary genetic helper is exact.

Native seeds are shared only within each background policy pair. The reader independently reconstructs every
purpose/generation/life ID and verifies64/48 unique IDs per arm, exactly27 shared IDs,85 per background and 170
across both. Confirmation has 512 additional disjoint IDs. These are deliberate paired policies, not four
independent search replicates. Half-life diagnostics reuse final-index0 IDs; the ten established seed11 goldens
remain separate from research IDs.

When all searches finish, the reader will reconstruct all four complete final populations and the first 256
candidate rows in each run. It requires byte-identical first cohorts across each policy pair and checks the
producer's retained instruction digest. Later trajectories may differ. This replays recorded operations,
not random-number draws or life simulations. Search shortlist means, status summaries and seed schedules are
checked; unsaved per-life training ledgers cannot be recovered. Native validation and tiny finals retain
summaries, so full raw-status reconciliation applies to the six confirmation rows rather than every search life.

Both fixed Z founders and all four final rank0 endpoints must be frozen together before confirmation. The
reader verifies all six 512-life raw 58-column rows, 61 named score columns, aggregates, identities, hashes,
timings and worker summaries. The two precision-minus-depth contrasts and four endpoint-minus-founder contrasts
retain every valid guard/extinction case with the unchanged production penalties. Income, all ordinary cost
categories, guard charge and extinction charge reconcile before paired mean/SE reporting. No late-window
AA assumptions are used here.

Resource checks require the actual persisted four-field process identities—pid,ppid,pgid,start_ticks—five owned
workers across the search and confirmation phases, all searches complete before confirmation, and a clean first
attempt within the included 9,000/7,200 CPU allocations and termination margins. No session ID is invented.
Executing analyzer/accountant/native/helper hashes and the pinned production definition closure are checked.
Missing or corrupt inputs yield incomplete status and no summary/vector output directory.

The 39 focused tests cover actual U/Y producer receipt formats, the current AB monitor's persisted schema,
synthetic complete/corrupt six-row ledgers, both weighting policies, archived seed-hash values, exact within-pair
sharing, all 256 first-cohort rows, and four-search completion/ownership/CPU failures. Synthetic numeric arrays
are engineering fixtures, not generated scientific candidates. The separate initialization receipt verifies
the actual prepared inputs. No simulation or compilation is part of these checks.

To analyze a terminal bundle into a fresh directory:

    PYTHONDONTWRITEBYTECODE=1 python analysis/analyze.py --study . --out /path/to/new/output

The archive resolves production sources from `production/`, external historical dependencies from `original/`,
and operational receipts from `operations/`. Tests and original helpers are retained for source review.
The comparison matches selection calls, not CPU or evolutionary depth. A fitness benefit can still be economy;
capture/low-light readouts do not establish memory or prediction. Fixed-genotype paired SEs do not measure
general search reliability across the two background/run pairs.
