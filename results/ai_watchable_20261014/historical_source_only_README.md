# AI viewer candidate — source only

This draft adapts the existing persistent-target viewer for the three fixed AI roles: the original AE L92 start, the ordinary control endpoint, and the reserve endpoint. It has not read AI genomes or outcomes. No JS or C life has been replayed, no input has been exported, and nothing has been published.

The illustration is fixed in advance to confirmation seed 52,360,000, the first recorded seed. Show all three roles simultaneously, including any duplicate genome. Do not search for a prettier seed or a life that agrees with the aggregate result. The aggregate table remains above the animations and retains reserve minus control, control minus start, and reserve minus start, including negative and unresolved estimates. Each row shows capture difference, production F, capture income, ordinary cost saving, guard saving, and extinction saving. Values are mean ± one paired standard error; the descriptive threshold uses the unrounded mean and SE. Confirmation lives are not independent evolutionary repetitions.

The template and viewer reuse the AE camera, body trail, target, and four-layer tissue display. Play, pause, restart, playback speed, resize, and hidden-tab pause affect viewing only. There are no organism, price, world, target, or seed controls. The maintained LifeSimJS file is referenced by its exact SHA and is unchanged. Equal seeds do not imply identical later target paths because placement depends on each body's actions. Rendering may process one panel ahead of another, so each panel displays its own time.

After a complete AI result, root can separately authorize the following bounded engineering work:

1. Verify the completed protocol, summary, budget, process clearance, endpoint manifest, three raw rows and genotype hashes; export all three fixed bodies through the existing ABI3 packer. `export.py` defaults to a source-only report. Its explicit export mode requires a root authorization file with terminal and draft-source hashes.
2. In one Node process, replay exactly those three existing lives with the unchanged engine and compare all 57 raw physical ledger columns bitwise against the retained C rows: 171 comparisons. This is reproducibility checking, not fresh scientific evidence. `run_validation.py` defaults to no replay, uses a 120 CPU-second / 180 wall-second ceiling when explicitly enabled, refuses an earlier attempt, and retains failures without automatic retry. No compiler or C/Python life is involved.
3. Build a fresh local standalone HTML only after export, replay, and mock UI checks pass. `build.py` refuses to overwrite the output. Root decides separately whether to publish it. A replay mismatch or failed AI study means no validated viewer claim; the draft is not a reason to substitute a role or seed.

The root authorization format is `status: authorized_AI_viewer_export_and_three_JS_checks`, `protocol_sha256`, `summary_sha256`, `terminal_clearance_sha256`, `budget_sha256`, and `source_pins` for the six export/view/build/replay sources. The protocol is already fixed at `0dc385199dc871a86f7a31a62c393b2c160f0cbae018ceece3ec8f51bb6dff00`. No such viewer authorization exists in this draft.

The mock-only UI test creates synthetic display states and synthetic positive and negative aggregate estimates. It loads neither the real simulator nor scientific data. It checks all three fixed roles, fixed seed, all contrast signs, threshold text, pause/restart, hidden-tab pause, completed-state controls, and finite drawing coordinates at two widths. Node syntax checks and this mock test are the only JavaScript execution performed so far. A Firefox binary is available, but no rendered real-browser test or screenshot has been performed; Node replay, mock controls, and actual-browser rendering are different checks.

Source history and exact origins are retained under `history/` and `source_origins.json`. The LGPL notice and license link remain in the template. Browser sessions can replay the illustration repeatedly when users press Restart; the proposed three-life count applies to the bounded validation invocation, not future user interaction.
