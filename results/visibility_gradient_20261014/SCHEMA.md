# Planned registration interface

This document describes the implemented driver contract. It is not a registration and contains no reserved seeds.

`protocol.json` must include:

- `world_decision: "complete"`, the exact `world` dictionary for `catch_speck_blink20_20_l4` atT1024, and `monitor_scope` exactly equal to `measure.SCOPE`/`monitor.SCOPE`.
- `seeds` with `screen`32, `confirm`512, and `calibration`2 explicit unique unsigned IDs. All stages must be disjoint and exclude the retained numerical golden seed11.
- `founder_raw_sha256` equal to the two constants in `measure.FOUNDER_SHA`, `mutation_rng` with one fixed RNG seed per background, and `panel_genotype_sha256` with all65 raw float32 row hashes for each background.
- `file_pins`: study-relative SHA256 pins covering the entire worker, monitor, inputs, configs, original mutation operations and panel manifests. `production_pins`: repository-relative pins covering all current `src/**/*.py`, the kernel, and the imported `taskvar_confirm`, `taskvar_gradient`, and `taskvar_gates` helpers. The final release must also pin the independent analysis and review artifacts.
- `numerical_identity`: exact source-only identity produced by the retained `numerical.identity()` helper, which initializes Torch before checking the runtime library map. This does not compile or simulate.
- `expected_startup_metadata`: the existing `src.checkpoint.numerical_identity()` dictionary excluding only `kernels` and `golden`. These fields can be captured through the corresponding source-only compiler/libm/Torch/NumPy/source checks. Do not execute `numerical_identity()` during preparation to obtain them: its two golden lives belong to the one monitored worker invocation.

For each `inputs/D90` and `inputs/L92`, provide `parent.json`, derived `config.yaml`, `genomes.npy` (float32[65,875]), `mutation_ops.json` and `panel_manifest.json`. Row0 must match the extracted founder exactly. The manifest binds `genomes_sha256` (raw table bytes), `mutants:64`, parent/config/mutation-operation file hashes, `mutation_seed`, `mutation_helper_sha256`, and the exact mutation dictionary `{n_mut:2,p_cell:.5,scale_n_mut:true,dup_rate:0,del_rate:0,split:false}`. All65 mutants/parent rows must be frozen before any scientific score. Do not regenerate or filter duplicate/no-op mutants.

The derived configs select `life.abi=4`, the exact blink preset andT1024, no T choices or physical/cost overrides, no envelope, and threads2. Preserve `life.extinct_charge=true`. The original source configs remain separately retained. Before simulation, `LifeEvaluator.world()` must exactly equal the pinned world.

`ready.json` follows the reviewed X2 monitor contract: status `released`, complete `source_pins` and identical `production_pins`. It additionally binds `protocol.json`, `monitor.py`, `resource_clearance.json` and every independent review artifact. The clearance lists exact exited prior PID/start-tick identities, owned process groups and terminal budget hashes. The monitor refuses any existing attempt, generated rows, cache, log or phase artifact.

The single worker receives `--run --monitor-pid PID` and `CELLDEV_GRADIENT_MONITOR_PID=PID`. The monitor writes and fsyncs `attempt.json` before spawning it, publishes a running budget, starts a new process group/session and applies the existing parent-death/resource guards. OMP threads and thread limit are2, other numeric libraries1; `CELLDEV_THREADS_FILE` is removed. Logs merge stdout/stderr under `logs/gradient.log`; compilation stays inside `build-cache/`.

Rows are `measurement/<background>/<calibration|screen|confirm>/row_NNNN.npz`. Each contains raw float64[lives,58] `ledger`, ordered uint64 `seeds`, scalar `genome_index`, scalar canonical JSON `identity`, nonnegative scalar `cpu_seconds` and `wall_seconds`, all58 ledger labels as production-derived columns, plus `F_kernel`, `extinct_charge`, and `window`. The named `F` includes the retained extinction penalty; raw ledger F does not. Identity binds protocolSHA, background, stage, genome index/hash and exact seeds. Per-background `row_index.json` pins each raw file hash and CPU; stage `scores.npz` stores the aggregate named columns without replacing raw rows.

The worker writes `startup_identity.json` after its sole numerical identity invocation and records which fields were preexpected versus newly captured. After four two-seed ABI4 calibration batches, it writes `requests/calibration_complete.json`, binding that startup receipt and both row-index snapshots. It waits for `monitor_receipts/calibration_complete.json`. The monitor checks ten validation lives, existing metadata, raw-file pins and cumulativeCPU below3390, then records its cumulative CPU and exact row snapshots. The worker uses that CPU in the fixed feasibility calculation.

After both screens, the worker freezes `selection.json` (one row1..64 and raw hash for each background), then writes `requests/screens_complete.json` binding selection and row-index hashes. The monitor requires a passing unchanged calibration projection, all130 screen rows, and both selected candidates in the registered panels. It observes cumulativeCPU below3390 before changing to the confirmation phase and acknowledging. The worker performs neither confirmation before acknowledgment.

Both receipts contain status `allowed`, `protocol_sha256`, `attempt_sha256`, `request_sha256`, `cpu_seconds`, `row_snapshot`, and `artifact_pins`. The latter permanently bind actual startup identity, selection and projection files. Later boundaries and terminal checks recheck those hashes. The worker's one total-CPU limit remains valid across the phase switch; the monitor separately enforces the earlier startup/screen ceiling.

`report.json` stays incomplete until all planned rows finish. Terminal completion requires69 pinned raw rows per background (2calibration+65screen+2confirmation), both acknowledgments, exact6,208 research/10validation/6,218 total lives, no changed earlier row, and committed row CPU no larger than monitored CPU. Independent analysis must verify raw rows, full58-column accounting, frozen whole-row selection, and paired confirmation; a worker report alone is not a scientific verdict.
