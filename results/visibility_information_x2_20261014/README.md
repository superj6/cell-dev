# X2: visibility information payoff (preparation)

This directory prepares a fixed information-payoff study for the approved flash and irregular-blink worlds. It contains no research results, new compiled libraries, seed registration, or release marker. The retained C5 controller source and every parameter remain unchanged; its source is copied into `original/controllers/` and hashed in `bundle.json`.

The first study contains 2 worlds × 13 fixed candidates × 512 paired T1024 lives (13,312 research calls), plus the exact 82-call validation package. The cumulative cap is 3,599 CPU-seconds, including compilation, validation, calibration, failures and teardown. Validation has its own 179 CPU-second cap within that total. The monitor uses at most two one-thread workers. Any failure ends this first attempt; there is no retry or resume.

Run `python prepare.py` or `python monitor.py` to inspect the dry-run plan. `prepare.py --prepare` copies and validates sources/metadata without compilation or simulation; it refuses an attempted or released study. It loads the archived ABI3 package first, and reads production ABI4 presets through a separate process. `validate.py` and `measure.py` also default to dry runs. They require the live, source-pinned monitor attempt and root release to execute.

Only the root agent may register the proposed primary block113 and validation block116, bind terminal resource clearance, and create `ready.json`. Blocks114/115 are held suggestions for a separately reviewed G5 extension and remain unreserved. The root readiness record must bind every protocol source pin plus the final independent analyzer, its tests and independent review receipts. Analyzer/review files live in `analysis/` after finalization, outside protocol file_pins to avoid a protocol/analyzer hash cycle. The analyzer is separately pinned by ready.source_pins.

After review and release, `python monitor.py --run` first compiles the four fixed validation libraries and executes validation; research starts only after all fixed checks pass within the same budget. The original ABI3 worker never imports the main ABI4 engine or uses an implicit compiler. Library metadata and every raw array shape/dtype/stride are checked before dispatch. The ABI4 physical bridge runs in a separate process.

Every research role writes all 512 ledgers to `rows/<world>/<role>/row.npz`, bound by an atomic checkpoint and a whole-world completion marker. Raw scratch columns21/22 explicitly mean dark/late captures. Independent analysis reconstructs the accountant from all57 columns and maps dark captures to the production low-light readout. Full I uses hollow3, the same56 cells as both reflex references. A and B are broad model/action interventions and cannot isolate memory. Capability-specific admission and G5 remain incomplete.
