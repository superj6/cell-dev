Preserving all 32 AF L92 final population rows is a stronger start for the ordinary-depth question than making 31 new mutations of rank zero. It retains the selected population and its frequencies after contraction, avoiding a new founder bottleneck. The existing public AF archive is sufficient: the raw checkpoint population, JSON population, founder, full recorded lineage, and prior independent replay bind every final row. Preserve row order and duplicates, plus a crosswalk from original AF IDs to the new study's IDs. No input is copied by this note.

The native `seed_genome` function currently returns one row; it does not accept a population archive. A narrowly pinned external founder-loader can instead return the exact retained float32 `[32,875]` table once. The existing `fill(founders, 32, ...)` then has zero copies to create. Its empty mutation path should receive a synthetic RNG-state check before release. Ordinary crossover, mutation, recheck, selection, and diagnostics remain unchanged. Bind the loader and input hash in configuration and extended numerical identity, as with AH's external-source binding, with one original identity call per worker.

This is a fresh run from a retained population, with a new genetic/tie seed and new audited life IDs. It is not an uninterrupted resume: old RNG states, scores, counters, and checkpoint identity are not imported. The native checkpoint validator deliberately rejects changing the old four-generation target. Native founder IDs, breed labels, and gene-slot origin labels would reset to 32 imported founders; record that mapping and do not interpret those new labels as biological innovations. Structural mutation remains disabled. The independent replay must start from all 32 fixed founders with an empty initial-copy list instead of its current one-founder assumption.
