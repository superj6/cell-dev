# AH prospective scientific contract

The fixed founder is AE L92 selected row 31, a deliberately chosen case motivated by AE's small capture gain and AF's later capture loss. This background choice uses those completed observations. AF is not reused as the control: both AH arms are fresh searches. AG's outcome sign is not a dependency. The world is exactly AE/V persistent-target ABI3 at T = 1,024, with target speed 0.3, mean turn interval 200, d0 = 1, d_min = 0.5, and the existing capture value 500. No organism behavior, task price, production default, or in-life rule changes.

Run order is `control`, `reserve`. Each run has four generations, 32 parents, 224 offspring, three initial lives per candidate, and four added lives for 64 rechecked candidates. Both arms share one native seed and the complete native life schedule. One ordinary 32-row initialization is prepared for later recorded-operation replay; the native workers independently reproduce that same initialization from the fixed founder and seed. Their first 256 candidate bytes must agree. All later ordinary mutations and recombinations remain native.

In reserve generations 0, 1, and 2, choose two distinct candidate positions uniformly from positions 32 through 255 by the declared stateless SHA256 rejection lottery. Eligibility ignores fitness, captures, morphology, and genotype. Form the shortlist from those two and the highest-ranked 62 other candidates. Order that set using the already-computed complete initial fitness rank. After four added lives, retain the protected two plus the highest pooled-fitness 30 others, again ordered by the complete pooled rank. The final generation uses the original recheck function. The control uses the original recheck function in all four generations. Ties retain the original randomized stable ordering and exact native permutation call sizes.

Both complete generation-4 rank-zero endpoints are fixed together before any confirmation row. Confirmation roles are `AE_L92`, `AH_control`, `AH_reserve`, with 512 shared fresh seeds and explicit duplicate roles if genotypes coincide. No endpoint substitution is allowed. All confirmation lives, including production guard and extinction penalties, enter the paired statistics. Invalid, nonfinite, mismatched, missing, or incomplete data prevents complete inference.

The primary estimate is the per-seed capture difference `AH_reserve - AH_control`. Report its mean and standard error; the descriptive evidence threshold is strictly mean > 3 × SE. Report production F and its additive capture-income, ordinary-cost, guard-charge, and extinction-charge decomposition for that same contrast. Retain both endpoint-minus-start comparisons, all signs, health, and genotype identities. No selection or scope decision uses confirmation results. Other metrics and ancestry are descriptive. These are fixed-genotype estimates from one selected evolutionary pair, not replicated evidence about the reserve policy's general reliability.

If captures improve while F declines, report the capture/fitness tradeoff. If F improves only through economy, report economy. More offspring ancestry or survival alone does not demonstrate a richer algorithm, memory, or a necessary stepping stone. Shared random streams improve comparability of the initial search conditions; later divergent genotypes mean the evolutionary comparison is not two independent replicates.

There are 4,096 selection calls, 32 periodic validation calls, and six tiny final diagnostic calls per arm, totaling 8,268 search calls. Three confirmation roles add 1,536. Exactly three numerical-identity invocations add six ABI3 seed-11 T200 golden calls, for 9,810 total. Two half-duration final diagnostic calls per arm intentionally reuse the final-index-zero life IDs. No extra startup calibration, resume, or live engineering check is included.

Budget: 5,400 CPU seconds inclusive, 3,400 seconds through search and at least 2,000 seconds reserved for confirmation, with ten-second cleanup margins. A metadata-only feasibility gate uses the largest measured per-life CPU rate among all 65 AE L92 screening rows. Search projection is `180 + 1.5 * 8268 * max_rate`; confirmation projection is `180 + 1.5 * 512 * 5 * max_rate`, allowing one maximum for the known start and twice that maximum for each unknown endpoint. Both must fit 3,390 and 1,990 seconds respectively. These assumptions cannot bound unseen mutants; hard monitor caps remain decisive. Matched simulation calls do not imply matched CPU.

The pilot is one attempt only. Both search workers must finish and their owned process groups must exit before confirmation starts. Any failure, incomplete phase, or budget stop remains archived incomplete. No retry, rescue, extension, alternate endpoint, or partial-result inference is authorized by this protocol. Clean AG terminal resource clearance is required; favorable AG outcomes are not.
