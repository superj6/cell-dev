# AD archive scope

AD changes the existing flash world's residual cue multiplier from 0.25 to zero. Its thirteen retained instruments, physical parameters, source definitions, historical timing rows, exact registered seed lists, current namespace audit, resource receipts and independent reader are included here. Only the I/B instruments' known dark-amplitude parameter changes to match the world; their algorithms are retained.

The scientific reader uses the bundled `inputs/`, `original/`, `production/` and operational receipts. Preparation is published before runtime release and contains no newly compiled AD libraries or simulated AD lives. One already published historical ABI4 bridge library is retained solely as provenance under `production/results/abi4_visibility_20261014/`; it is not the AD runtime library.

Complete historical seed-namespace verification additionally requires five older objects already committed in the **cell-dev repository**. The exact repository paths, containing commit, SHA256 and byte lengths are listed in `original/outputs/audit_visibility_dark_tail_information_20261014/namespace_history_references.json`. These 32,410,728 bytes are referenced instead of copied again. Thus the standalone AD folder contains its scientific inputs but not the entire historical namespace evidence. The current audit's explicit limits and classified synthetic fixtures remain in its retained receipts.

The archive helper verifies those historical objects against both current repository bytes and the stated Git commit. Neither the helper nor the scientific reader downloads missing evidence. The preparation portability audit restricts external scientific inputs to this archive's `production/` and `original/` directories; it does not silently fall back to live source.

Frozen source-only descriptions and pre-registration seed-review wording remain historical evidence. `PREPARED_STATUS.json` records preparation status; `prelaunch/manifest.json` preserves the exact prospective artifact bytes. A later terminal archive can append raw outputs and runtime receipts without replacing the preparation.
