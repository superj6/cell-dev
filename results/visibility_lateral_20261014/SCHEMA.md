# AA producer and offline-reader contract

Source-only schema. A final protocol will be generated only after registered terminal Z inputs exist. Independent analyzer/review artifacts can be bound separately in ready.source_pins to avoid a protocol/analyzer hash cycle.

Registration: status=registered, labels in exact six-role order, conditions in exact three-condition order, seeds128 unique integers excluding11, seed_audit_sha256, and Z_complete={file_pins,summary_path,summary_sha256}. Its required Z pins include protocol,budget,confirmation/endpoints.json,genotypes.npz,row_index.json,report.json. seed_audit.json has status=passed and exact seeds. Root owns these records.

Protocol: study='AA fixed-tissue blink lateral dependence'; labels/conditions/seeds; T1024,t_fork512,t_open544; worlds full physical dictionaries; unmodified_world copied from Z; planned_genome_lives2304,startup_validation_genome_lives2; max_cpu_seconds1200,max_workers1,max_simulation_threads2; primary_pairs[[4,2],[5,3]],start_pairs[[2,0],[3,1]],cumulative_pairs[[4,0],[5,1]]; genotype_sha256 mapping; genotypes_file,layout_file,config_file; cost_projection; numerical_identity metadata; expected_numerical_identity full prior Z golden/library record; file_pins study-relative and production_pins root-relative.

Inputs: exact copies under inputs/Z of completed protocol,budget,endpoint manifest,genotypes.npz,row index,report and all six full512-life confirmation rows for cost evidence. inputs/Z/evaluator.yaml is an unchanged Z evaluator config; inputs/Z/layout_reference.json is the originalD90 layout/genome serialization. Genotypes NPZ contains genomes float32[6,875] and labels strings. No new genotypes are generated. inputs/Z_summary.json retains the reviewed complete analysis and inputs/Z_cost_rows.json records row pins/cost projection.

Monitor: attempt.json contains monitor={pid,ppid,pgid,start_ticks} and ready_sha256. budget.json contains status,cpu_seconds,cap_cpu_seconds,wall_seconds,phase='measurement',running map,queued list,completed [{name,exit_code}],affinity,ready,process_identities,owned_process_groups,reason,exit_code and cleanup_error when relevant. There is no persisted sid field. Worker must descend directly from the live monitor identity and own its process group/session; an empty running map at immediate startup is permitted. Any prior runtime artifact blocks a new attempt.

startup_identity.json: identity (complete existing numerical_identity result), protocol_sha256,startup_validation_genome_lives2,comparison. Exactly one numerical_identity invocation inside measure(), no preparation or monitor golden prepass. Runtime-only numerical.check occurs in monitor/worker and imports Torch consistently.

Each measurement/<condition>/row_000i.npz: identity scalar JSON, seeds uint64[128], genome_index scalar, ledger float64[128,58], cpu_seconds and wall_seconds scalars, all58 named production columns plus F_kernel,extinct_charge,window. NamedF is production fitness; raw ledgerF and F_kernel are kernel fitness. identity includes protocol_sha256,genotypes_sha256,role,condition,stage,genome_index,genome_sha256,seeds. Measurement condition order is normal,freeze,freeze+lateral_off; genome order0..5. row_index.json maps condition/filename to {sha256,cpu_seconds}. Each condition scores.npz retains seeds,genome_indices and all61 column matrices[6,128].

report.json: status complete only after18 rows, genome_lives2304,paired_seeds128,startup_validation_genome_lives2,protocol_sha256,startup_identity_sha256,row_cpu_seconds,labels,conditions,frozen_checks,contrasts,absolute,limitations. frozen_checks reports coverage perlabel, window[544,1024], and all_fitness_rows_retained.

For each metric, contrasts returns36 vectors: six fixed pairs ×(three gains+added_lateral_dependence+gain_lost_under_freeze), plus six own frozen_lateral_loss. Pair prefixes are family+'__'+winner+'_minus_'+parent, with family primary/start/cumulative. Gains append '__gain__'+condition; interactions append '__added_lateral_dependence' or '__gain_lost_under_freeze'. Own losses use label+'__frozen_lateral_loss'. Signs: added lateral=gainFreeze−gainFreezeLateral; lost under freeze=gainNormal−gainFreeze; own loss=Freeze−FreezeLateral. paired.npz keys are metric+'___'+contrast; report.contrasts stores mean,se,n for each. Absolute stores the same statistic permetric/condition/label.

Metrics are F,F_kernel,captures,low_light_captures,clicks,misses,spikes,kappa_sum,contact_events,rec_gain,income,cost,guard_charge,extinct_charge,live_time,n_end,n_S_end,n_M_end,n_H_end,last_birth,path,bright_captures,capture_income,ordinary_cost_saving,guard_charge_saving,extinction_charge_saving. Last four additive values are income/480,−reconstructed_ordinary_cost/480,−guard/480,−extinct_charge, respectively, and must sum toF. The independent accountant can retain its own positive-cost naming internally, but serialized producer signs are fixed here.
