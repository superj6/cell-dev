Z: short ordinary evolution in irregular blink

This study is registered for one-time preparation and remains unreleased. Terminal
Y is complete and independently analyzed. The fixed starts are D90's Y row58 and
L92's Y row24, assigned native runs53220/53221. Both starts are retained regardless
of their fresh Y confirmation signs. The prepared protocol and initialization
receipts bind the exact source, input bytes, operation logs and RNG hashes.
Preparation compiles no library and runs no life.

The native evolution runner is unchanged. Each background receives four ordinary
generations with 32 parents and 224 offspring, three shared initial lives and four
additional lives for the top 64. All six fixed confirmation roles share 512 new
seeds: original D90/L92, their Y-selected starts, and both final population rank0
endpoints. The endpoint pair is frozen before any confirmation. The comparison
separates capture income, ordinary operating costs, guard charges and extinction
charges; low-light captures remain a diagnostic, not a claim of memory.

The fixed scope is 8,268 search/diagnostic lives plus 3,072 confirmation lives,
and six existing ABI3 T200 startup goldens: 11,346 total calls. Search and startup
have a 3,600 CPU-second ceiling; 3,600 seconds are reserved for confirmation and
cleanup within a 7,200 total cap. The stop margins are 3,590 and 7,190 seconds.
Search uses two workers with two simulation threads each; confirmation uses one
worker with two threads. Existing native checkpoints pin deterministic replay.
There is no automatic restart, retry, founder substitution or budget extension.

Y's four completed ABI4 confirmation rows supply a prospective cost estimate for
the actual developed founders: 3,115.984392 CPU seconds for startup/search and
1,582.851613 for confirmation under the predeclared formula in PREREG.md. These
fit the allocation but cannot bound slow new mutants. No extra calibration lives
are hidden in preparation. Confirmation uses new block120 at base51M,
52,200,000 through52,200,511; no extra validation block is reserved.

`prepare.py`, `run_budgeted.py` and `measure.py` are dry-run by default. The explicit
preparation command is guarded by root registration, complete Y evidence, a seed
audit and a once-only population generation claim. A later release requires exact
source/config/analysis pins and process clearance. Only the root releases the
monitor with `run_budgeted.py --run`. No command is authorized by this README.

The score adapter and numerical runtime helper are byte-for-byte copies of Y.
The monitor retains U's owned process-group cleanup and CPU accounting. The only
new orchestration is the six-role ABI4 confirmation and terminal Y input binding.

Output schema after a future release:

- `protocol.json`, `registration.json`, `seed_audit.json`, `initialization.json`
  and pinned input/config files bind the fixed study. Analysis and review files
  may be separately bound in root's `ready.json` to avoid a hash cycle.
- `runs/s<seed>/` contains unchanged native checkpoints, identity, curves, lineage,
  population, best-genome and tiny final diagnostics. Final rank0 is selected only
  from the complete generation4 checkpoint and checked against best_genome.json.
- `confirmation/endpoints.json` binds both endpoints, four fixed references,
  world, seeds, source identity and checkpoint/log hashes before scoring.
- `confirmation/genotypes.npz` stores float32[6,875] plus six ordered labels.
- `confirmation/blink/row_0000.npz` through `row_0005.npz` store uint64[512] seeds,
  float64[512,58] raw ledger, all 61 production named columns, scalar CPU/wall
  timings and JSON identity. Raw F_kernel differs from production F by the
  retained extinction charge. Row index and scores.npz bind the complete matrix.
- `confirmation/report.json` is a worker report only. Independent offline analysis
  must reconcile every raw row, the genetic trajectory and monitor evidence.
  `budget.json` records the search CPU at transition, total CPU, child exits,
  process identities and owned groups. A clean complete budget alone is not a
  scientific result.
