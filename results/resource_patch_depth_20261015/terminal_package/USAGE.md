# Terminal staging

These helpers are prepared source only. Run after the complete study, independent accounting and genetic
receipts, and saved-data tables exist, following root review. They neither run organisms nor install public files.

```sh
PYTHONDONTWRITEBYTECODE=1 /usr/bin/time -v -o <external-resource-log> timeout 35s .venv/bin/python outputs/resource_patch_depth_20261015/terminal_package/pack.py --readme outputs/resource_patch_depth_20261015/TERMINAL_README.md --report outputs/resource_patch_depth_20261015/REPORT.md
```

The default fresh stage is `outputs/resource_patch_depth_terminal_stage_20261015`. The process is limited
to one CPU affinity, 15 CPU seconds, 30 wall seconds and 2 GiB address space, with 4 GiB host headroom.
Preserve failures; do not retry automatically. Root reviews and installs the staged archive separately.

The prospective manifest, README and publication helpers remain under `registration/`; every other
prospective artifact remains byte-identical at its original path. The new manifest binds the full terminal
file set, protocol, release, summary and registration. All eight selection arrays, native checkpoint/logs,
nine raw/scored cohorts, frozen endpoint files, phase startup raw, ownership records, audit sources/receipts,
tables/plots and root prose/reviews are included. Caches and test fixture trees are excluded. The two exact
compiled identity binaries and all pinned production sources are retained explicitly. Borrowed audit helpers
are copied unchanged under `audit_dependencies/`, preserving their original paths and hashes in the audit receipt.

Archive verification uses hashes and receipt schemas, without importing the simulator, Torch, NumPy or the
scientific analyzers. It does not rerun the independent arithmetic audits. From the repository:

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python outputs/resource_patch_depth_terminal_stage_20261015/verify.py
```

Use `--archive <path>` for another location, or `--installed-sources` to additionally compare installed
production files. The default verification depends only on files inside the terminal archive; prior public
dependency paths remain provenance metadata. The archived analysis/audit scripts retain their original
repository-relative execution assumptions and have not been rewritten for standalone reanalysis.
