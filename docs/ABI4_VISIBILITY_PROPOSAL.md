Approved scope (user, 2026-10-14): add flash and renewal blink as a small ABI 4 world extension. The user approved this proposal; implementation and compatibility checks are now in progress. This document proposes a narrower first step than plan 0.7's combined motor-flip/blink/flash port.

I recommend **flash plus renewal blink**. In flash, a target gives a short strong cue, then only a weak cue: useful behavior can depend on information gathered earlier. In renewal blink, the target becomes completely invisible for irregular intervals while it keeps moving: retaining and updating an estimate can pay during the gap. Evolution would discover how to do that using the existing local cells. Neither world tells cells the target's position, visibility state, or time.

| Scope | Scientific value | Engineering tradeoff |
|---|---|---|
| Flash only | Strongest retained information payoff; one bright window after each placement | Smallest scheduler change, but residual cues can support weak-signal tracking and the fixed window permits timing strategies |
| Flash plus renewal, recommended | Adds complete cue loss with irregular intervals; separates two useful environmental demands | Shares the same visibility state, rate multiplier and readout; adds one dedicated random stream, recurring transitions and their tests |

The retained 512-paired-life measurements give information-controller gains at the reflex's own footprint of **+8.041 ± 0.146 F** for flash and **+5.662 ± 0.133 F** for blink 20/20. On the larger selected controller footprint, idling when the controller believes the target is dark loses 24.607 ± 0.218 and 3.555 ± 0.163 F respectively. About 86% and 25% of extra captures occur in the low-light phase. These motivate access to the worlds; they do not establish an evolved memory algorithm. Those controller comparisons include free central computation, and the idle intervention changes actions as well as use of past information. Blink's separate no-dark-model contrast is only +0.529 ± 0.155 F. Flash still provides weak target pings. The archival admission code used an older do-less threshold; current plan 0.4 remains authoritative.

The exact reference is [the retained renewed harness](../../results/open_headroom/harness/make_ckernel.py), with world definitions in [mcommon.py](../../results/open_headroom/controllers/mcommon.py) and measurements in [memory.json](../../results/open_headroom/data/memory.json). The older [kernel_x.diff](../../results/taskvar_study/engineering/kernel_x.diff) uses a periodic square wave and broader world epochs; it is not the proposed blink. The scratch harness aliases reserved fields and ledger columns and embeds central controllers. Only its visibility physics supplies the reference semantics.

Proposed contract, to be reviewed before code:

| Appended world index | Field | Default | Meaning |
|---|---|---:|---|
| 66 | `visibility_mode` | 0 | 0 steady, 1 flash, 2 renewal |
| 67 | `visibility_on` | 0 | Flash bright duration, or renewal mean bright duration |
| 68 | `visibility_off` | 0 | Renewal mean low-light duration |
| 69 | `visibility_low` | 1 | Target signal multiplier during low light |

The world vector grows from 66 to 70 values. Enabled modes apply only to single-target CATCH (`b2_amp == 0`); existing two-blob worlds remain available with mode 0. Mode 0 requires the default tuple `(0,0,0,1)`. Flash requires positive `visibility_on` and zero `visibility_off`; renewal requires both durations positive. Positive durations lie in `[2^-10, 2^30]`, all values are finite, the multiplier lies in `[0,1]`, and the mode is an exact integer. ABI 2/3 callers reject enabled visibility rather than silently accepting an unsupported world.

Initial named presets would be `catch_speck_flash5_dim25_l4` with `(1,5,0,0.25)` and `catch_speck_blink20_20_l4` with `(2,20,20,0)`, inheriting every other field from `catch_speck_l4`. This retains the measured old conduction values (`d0=1`, `d_min=0.5`) for the initial bridge. Faster conduction, POOL combinations and other durations can be specified and measured subsequently; their information payoff is not assumed from these historical scores.

Both modes start bright at `t0`. Flash becomes low light five time units after **every** target placement, including initial, timer-driven and capture-driven replacement. A new placement replaces the old deadline and restores brightness. Renewal alternates independently drawn exponential bright and low-light intervals; its initial bright interval is also exponential. Its schedule continues across target replacements. Use appended stream `S_VISIBILITY=26`, keyed by `(seed,26,0,k)`, and the existing `poisson_next` arithmetic. All previous streams retain their numbers and draw counters; flash consumes no visibility random draws.

Visibility is processed as an external world event. Preserve the existing left-limit rule: `world_to(t)` consumes events strictly before `t`. Equal-time target timers precede turns, which precede visibility transitions. Thus a timer placement exactly at an old flash deadline resets that deadline first. Capture replacements keep the existing deferred-placement order. A scheduled visibility transition gets world hash record `[14, dbits(t), 0, bright]` in `world` and `all`; initial brightness and flash resets are determined by the existing placement records. Emit no visibility records in mode 0. The browser event log may display visibility, but that display is not an organism input.

Only the target's contribution to the existing receptor rate changes: `lam_bg + (bright ? 1 : visibility_low) * (lam_s * halo)`. Background pings continue during darkness. The current bright-state candidate-rate bound stays valid. Target movement, placement distribution, capture radius, reward and action costs retain their existing rules. World scheduling is simulator bookkeeping, like today's target turns and respawns; it adds no shared cell tick or phase signal. Flash's reset after capture follows the target's ordinary replacement, with no response to population performance.

Append one readout, `low_light_captures`, at ledger index 57: counted target captures made while the visibility state is low, using the same accounting window and pre-replacement state as `captures`. It is zero in mode 0; total captures already supply the denominator. Keep all 57 existing columns, including `beats` and `P_int`, in their existing roles. The ledger grows to 58 columns. Genome length, gene inputs, phenotype knobs, receptor modalities, messages, flags and organism update rules do not change.

Implementation scope is `docs/LIFE_ABI.md`, `src/life/spec.py`, `src/life/kernel.c`, `src/life/reference.py`, ABI packing/loading/export helpers, the maintained `results/atlas/play/lifesim.js`, and focused compatibility/parity tests. Add explicit `V4`; keep existing caller defaults and explicit `V2`/`V3` contracts. The current `CURRENT` is still `V2`, so changing it is not part of this proposal. ABI 3 worlds pad with the neutral tuple. Their returned 57 columns and five hashes must remain byte-identical: extend the existing close-hash unfolding adapter to remove the extra ABI 4 ledger fold. Raw ABI 4 `all` includes that extra fold and therefore need not equal the ABI 3 `all`, even with neutral visibility. Preserve old numerical/source pins; never bypass an old checkpoint's strict resume check.

JS currently supports a narrower world subset than C/Python and rejects the second blob. Add these worlds to its automatic single-target mode. Reject switching an enabled visibility world into interactive user-target mode until that separate behavior has a specification; ordinary mode-0 interaction remains as today. Do not rewrite pinned historical viewer copies. No central-controller callbacks, motor flip, payoff epochs, family scheduler, population response or paid compute enter this port.

Acceptance would require:

1. Existing ABI 2/3 regression and resume checks, plus neutral ABI 4 projection against pinned pre-change truth lives. All legacy ledger bytes, hashes, raster/fate outputs and invalid-world decisions must agree where their existing contracts apply.
2. C/Python/JS full-mode truth parity for the new single-target worlds, with deterministic repeat/thread tests and C fast/full ledger equality. Compare every ledger byte and all five meaningful full-mode hashes; fast-mode hash constants do not constitute replay evidence.
3. Focused boundary fixtures: initial phase, exact transition time, flash reset before/at expiry, capture and timer replacement, renewal persisting across replacement, nonzero `t0`, accounting-window/end boundaries, multipliers 0/1, validation and receptor-rate bounds. Use existing bodies as execution fixtures, without requiring that any fixture wins.
4. A bounded bridge to the retained scratch visibility physics using the exact mapped world values and unchanged tissue fixtures. Compare unchanged physical ledger columns; exclude the scratch's repurposed `beats`/`P_int`, check their production values retain their original meaning, and map scratch `dark_caps` to the new readout. New visibility hash records deliberately differ from the scratch harness; physical ledgers and action traces must reconcile. Retain source and seed receipts.

After acceptance, freeze each proposed research world and assess information payoff under plan 0.4 with fresh, tuning-disjoint pairs, then report a bounded evolution/confirmation budget before launch. G5's T768/T1536 checks remain outstanding for these capability worlds. A successful port is engineering evidence, not automatic approval of the large F/M/W selection matrix. Fitness gains, persistent firing, residual motion or cheaper bodies alone would not demonstrate memory; capture timing, costs and suitable causal contrasts remain necessary to interpret what evolved.
